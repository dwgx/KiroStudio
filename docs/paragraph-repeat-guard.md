# 段落/句子级复读检测器 —— 设计与误报分析

> 结论先行（详见 §7）：**通用「改写式复读」检测器不该带执法上线**。实测特征空间是**倒置**的 —— 一类
> 合法内容（agentic 模板化叙述）相似度 **0.892 高于真实退化语料的 0.856**。能分开两者的判据存在，但
> 要靠「相似度 + 差异点离散度」二维带状门，且只拟合了 **n=1** 条正样本。建议只做**纯观测**（默认关、
> 不截断），拿到线上基率后再谈执法。执法版按 `stray_guard_tripped` 那样截断本轮 = 用户答案被静默
> 切掉，代价与收益不对称。

## 0. 实测基线（本设计的全部依据）

只读语料 + 一次性脚本测得（脚本未入库）。归一化 = NFKC + 小写 + 只留 alnum；`cont` = 5-gram
shingle containment（交集/较小集合），`diff_sites` = 归一化串上 `SequenceMatcher` 的非 equal
opcode 数，`symr` = 非 alnum 占比，`terms` = 句末标点数。

| 样本 | norm 长 | cont | diff_sites | symr | terms |
|---|---|---|---|---|---|
| **真实退化语料**（A vs B） | 171 | **0.856** | **6** | 0.153 | 5 |
| 合法·模板叙述（只换 id） | 125 | **0.892** | 2 | 0.113 | 4 |
| 合法·模板叙述 + 轻改写 | 125 | 0.563 | 11 | 0.113 | 4 |
| 合法·参数化测试体（未围栏） | 124 | **0.825** | ~5 | 0.275 | 2 |
| 合法·Markdown 表格块（本仓文档） | 106 | 0.069 | — | 0.197 | 0 |
| 合法·文档同事实复述 | 61 | 0.156 | 7 | 0.103 | 2 |
| 合法·副歌逐字重复 | 58 | 1.000 | 0 | 0.134 | 3 |
| 合法·中英翻译对照 / 简繁对照 | 13~34 | 0.000 | — | — | 0 |

两条**决定性**观测：

1. **单阈值 containment 不可用**。任何 `cont >= T`：`T ≤ 0.856` 必然连带命中模板叙述
   （0.892），`T > 0.856` 则漏掉唯一的真实语料。不是调参问题，是类别顺序反了。
2. **长度门比相似度门承重得多**。绝大多数误报类（表格/列表/栈帧/JSON/翻译）归一化后只有
   9~47 字符，真实语料 171。`min_norm_len` 一道门挡掉大半，且**不依赖**对退化形态的猜测。

补充：真实语料逐句 containment `1.00/1.00/0.83/1.00/0.87/0.67`，归一化后逐字相等 3/6 句 —— 改写
发生在句内局部，整段骨架不变。

## 1. 候选算法

流式约束（三者共有）：不能等完整响应；跨 chunk 有状态；**不得跨 chunk 持有原文**（`invoke_sniff_buffer`
无界持有已出过 #14 那样的整流停摆事故），只能持定长指纹。

**A. 句子级归一化哈希 + 有界环**（推荐做观测层）。按 `[。！？!?;；\n]` 切句 → 归一化 → `u64`
哈希 → 查最近 K=64 条环形多重集，同哈希 ≥N 次即计数。每 chunk O(len)、查表 O(1)；内存
**K×16B ≈ 1KB/请求**（只存哈希不留原文）—— 唯一能在 O(1) 内存下工作的方案。劣势：只抓「改写后
仍有整句逐字相同」，本语料 3/6 句命中（骨架句 `🔴 找到了，是一个词的问题` 逐字复现），纯改写抓不到。

**B. n-gram 指纹 winnowing + containment**（推荐做判据核心）。5-gram 滚动哈希 + winnowing(w=8)
降采样约 1/4，存最近 M=2048 指纹的环 + 段落起止标记；段落闭合时与环内 ≤8 候选段算 containment。
滚动哈希 O(len) 摊还、比较 O(候选×指纹)；内存 **16KB/请求**。能处理改写式重复、对插入删除稳健。
劣势：**单用必误报**（§0 第 1 条），须叠 diff_sites 门。

**C. 最长重复子串（后缀自动机）** —— 不适合：只认逐字重复（本语料改写后最长公共子串远短于整段），
内存 O(len) **无界**，与 `MAX_BUFFERED_EVENT_BYTES` 那类隐患同源。

**D. 压缩率** —— 否决（列出以免重提）：表格/JSON/缩进代码/日志压缩比天然极低，与退化不可分；
且它是**整窗标量**，定位不到重复段落，做不了温和处置。

选定组合：**B 出候选（containment ≥ 0.80）→ 叠 A 的整句相等作为加权 → 叠 diff_sites ≥ 4 排除模板
替换。** `diff_sites` 是把 §0 那对倒置样本分开的**唯一**判据：真实语料 6 个离散差异点（分布式改写），
模板叙述只有 2 个（局部 id 替换）。代价是 `SequenceMatcher` 类 O(n·m)，仅在 containment 已命中时对
≤8 个候选跑一次，热路径正常文本零开销。

## 2. 🔴 误报清单

四道**合取**门（全须满足才判复读）：**G1** `min_norm_len >= 120`；**G2** `sent_terms >= 2`
且 `sym_ratio <= 0.30`（是散文，非结构/代码）；**G3** `containment >= 0.80`；
**G4** `diff_sites >= 4`（分布式改写，非局部替换）+ `occurrences >= 3`。下表逐类说明哪道门挡住它。

| 类别 | 为什么像复读 | 拦它的门（实测值） | 残余误报概率 |
|---|---|---|---|
| **歌词/诗歌/副歌** | 副歌逐字重复，containment=1.000 | **G1 + G4**：副歌单段 norm 长 58 < 120；且逐字重复 `diff_sites=0` < 4 | 低。残余：用户要求「输出完整歌词」且副歌本身 >120 字符又被改写 —— 罕见 |
| **Markdown 表格** | `\| --- \|` 行与同构行大量重复 | **G2 + G3**：分隔行归一化后长度 **0**（全是标点）；本仓文档相邻表格块 cont=**0.069**、terms=**0** | 极低。表格行天然无句末标点 |
| **代码（import/`}`/样板）** | 逐行同构 | **G2**：`import` 行 cont=0.526 且 terms=0；`}` 归一化后为空 | 低 |
| **代码（参数化测试体）** | 两个测试只差标识符，cont=**0.825**、norm 长 **124** | **G2 边缘**：symr=**0.275** 逼近 0.30、terms=2 刚好达标 → **仅靠 G3(0.825<0.80 不成立) 挡住，余量 0.025** | 🔴 **中**。这是最危险的一类。围栏内代码可用现有 `code_fence_open` 排除，但**未围栏**的测试体没有保护 |
| **重复日志行/堆栈帧** | 逐行高度同构 | **G1 + G2**：栈帧 norm 长 23、cont=0.211、terms=0 | 极低 |
| **列表 `- item` × 50** | 大量同构短行 | **G1**：单项 norm 长 15~24；实测两项差异项 cont=**0.091** | 极低。残余：每项都是长句且只差人名 → 但那时 `diff_sites` 小，G4 兜住 |
| **JSON / YAML 数组** | 元素结构相同 | **G2**：元素 cont=0.643 但 terms=0、symr 高 | 极低 |
| **翻译对照（多语言）** | 同一句多次出现 | **G3**：中↔英 cont=**0.000**（无共享 shingle）；**简↔繁 cont 也是 0.000**（字面不同） | 极低。反而是 containment 最擅长的一类 |
| **数学推导（同式多次变形）** | 同一式子反复出现 | **G1 + G2**：推导步骤短、符号占比高；实测两步 cont=0.000 | 低 |
| **本仓自己的文档**（重复表格 + file:line 列表） | `CLAUDE.md` 有大量同构表格行与 `xxx.rs:123` 列表 | **G2 + G3**：表格块 cont=0.069/terms=0；file:line 列表符号占比高、无句末标点 | 极低 |
| 🔴 **agentic 模板化叙述**（清单里没有，但它是本网关的**主流量形态**） | 「检查凭据 A…」「检查凭据 B…」逐轮复现，cont=**0.892 > 真实语料 0.856** | **只有 G4**：`diff_sites=2` < 4 | 🔴 **中高**。一旦模型在模板里顺手改一两个词（`接着看`/`同样`），diff_sites 就上去了；实测「模板+轻改写」cont 掉到 0.563 反而安全，**危险区正是「模板 + 3~4 处小改写」这条带**，而它在 Claude Code 的循环里完全正常 |
| 🔴 **extended thinking 的自我纠正** | 思考流天然把结论换着说法复述 3~5 遍 | **无门可拦**。且现有 `stray_guard_filter` 的调用点（`stream.rs:1468`）**在 thinking 分支（:1478）之前** → 段落检测器放同一处会**一并过滤 thinking 文本** | 🔴 **高**。这是不该在此处插入段落级检测器的独立理由 |

两处与误报同源的实现陷阱：① `process_reasoning_content`（`stream.rs:1965`）**不经过**
`stray_guard_filter`，结构化 reasoning 流根本不会被检测器看到 —— 判据在两条 thinking 路径上
不对称（与 #12 同型的读写键不一致）。② 用户显式要求「把这段重复 5 遍」是合法请求，任何段落级
检测器都会判成退化，且无法从文本侧区分意图。

## 3. 阈值与取舍点

| 参数 | 取值 | 依据 |
|---|---|---|
| `min_norm_len` | **120** 归一化字符 | 真实语料 171；最长的误报类样本 125（模板叙述）/124（测试体）。**注意 120 并没有把这两类挡在外面** —— 它挡的是表格/列表/栈帧/JSON（9~47）。取 120 而非 160 是因为 n=1，把门抬到贴着唯一正样本（171）就是过拟合 |
| `containment` / shingle k | **≥ 0.80** / **k=5** | 真实语料 0.856，不能取 0.85 以上（余量归零），也不能只靠它（模板叙述 0.892 更高）。k=3 时 cont=0.901 判别力被抹平，k=10 时 0.765 对改写过敏，5 是实测拐点 |
| `diff_sites` | **≥ 4** | 真实语料 6，模板替换 2。这是唯一分开倒置样本的门，**也是整套判据里最脆的一环**（n=1） |
| `sym_ratio` | **≤ 0.30** | 测试体 0.275 —— 余量只有 0.025 |
| `sent_terms` | **≥ 2** | 排除表格/列表/JSON（全为 0） |
| `occurrences` | **≥ 3** | 语料是 4 遍。取 3 而非 2：合法的「说一遍再复述一遍」极常见，两遍绝不能判 |

**「宁可漏检也不误伤」的取舍点**：漏检代价是用户看到复读四遍但**内容完整**、重发即可，且退化响应
本来就耗尽 max_tokens（异常一眼可见）。误伤代价是答案中途被静默切掉、**无错误信号**、半截文本进
下一轮历史（`stray_guard_tripped` 只丢弃剩余，不回滚已发）。前者可自愈，后者不可观测且污染上下文。
故取舍点定在：**任何一道门的实测余量 < 0.05 或只有 n=1 支撑，就不能带执法上线**。按此标准
`containment`（0.856 vs 0.892 倒置）、`diff_sites`（n=1）、`sym_ratio`（0.025）**三门全不达标**。

## 4. 熔断后的行为

现有处置（截断本轮剩余 + 置 `stray_guard_tripped` 永久丢弃）对**短 token 洪水**是对的：那种内容
100% 是垃圾，早截早止血。对段落级复读**不适用**：

- 段落复读的**第一遍是有效答案**（本语料第一段就是完整正确的结论）。截断点必须落在第 3 次出现的
  起点，前两遍保留 —— 是「只截重复部分」而非「熔断本轮」。
- 不应置永久 tripped：退化后模型可能恢复吐正常内容（不像短 token 洪水必然一路烂到底），永久标志
  会把恢复后的正文也丢掉。
- 建议处置 **折叠（fold）**：从第 3 次重复的段落起点截断本 chunk，计数 +1，不置永久标志；同请求内
  累计折叠 ≥3 次再升级熔断（此时可判定确实进入死循环）。必须 bump **独立**计数器，不要复用
  `stray_guard_tripped` —— 否则面板分不清「短 token 洪水」与「段落复读」（与 #21 同型问题）。

## 5. 配置项

**新增独立开关 `paragraphRepeatGuard`，默认 `false`，不复用 `toolStrayRepeatGuard`。** 理由：现有
开关语义是「stray token（call/count/card/court）复读熔断」，判据/阈值/处置全不同；复用会导致运维
想关段落检测时连带关掉已验证有效的短 token 熔断（#70544 的止血手段）。默认关是因为本仓 `tool*`
七项默认全开都有实测支撑，这一项没有（§7）。三层镜像照 `tool_stray_repeat_guard` 现成范式：

## 7. ⚠️ 值不值得做

**通用「改写式段落复读」检测器：不该做（至少不该带执法上线）。** 三条依据，按强度排序：

1. **特征空间倒置，不是调参能解决的**。合法 agentic 模板叙述 cont **0.892** 高于真实退化
   **0.856**，而模板化叙述正是本网关的主流量形态（sub2api → Claude Code 循环）。要分开只能靠
   `diff_sites` 这道**只有 n=1 支撑**的门，且 §6 测试 #12（模板 + 轻改写）按当前判据大概率
   FAIL —— **构造得出测试，但它是红的**。本仓先例 `clone_seq` 连续性约束因「构造不出测试」
   判不该做；这里更糟：承重测试与正样本测试**互相矛盾**。
2. **误伤代价不可观测且污染上下文**（§3）：截断无错误信号，用户以为答完了，半截文本进下一轮历史。
   漏检代价只是用户看到四遍复读、内容完整、重发即可。两者不对称。
3. **插桩位置本身有问题**：现有 guard 调用点在 thinking 分支之前，放同一处会过滤思考文本，而
   thinking 的语义复述是**健康行为**。放对位置要改 `process_assistant_response` 的结构，那是
   2600 行文件里的热路径。

**值得做的替代**：

- **阶段 1（建议做）·纯观测**：按 §1-A（句级哈希 + 64 环，1KB/请求）只累加计数、**不改输出**、默认关，
  经 `recovery_metrics` 暴露面板。与本仓 `observe_stray_leak_forms`（`stream.rs:3597`）同一范式 ——
  那个探针的存在理由正是「线上全 0 无法区分没泄漏还是没检测到」。段落复读现在同样状态：**只有一条
  语料，不知道基率**，而这个数决定后面还要不要做。
- **阶段 2（有条件做）·只在窄形态执法**：若观测显示复读集中在**近逐字**重复（`diff_sites` 小、
  cont > 0.95），那道门对所有误报类余量都大，可执法，处置用 §4 折叠而非熔断。**但那不是本语料的
  形态**（diff_sites=6），故不能预设会发生。
- **不该做**：把通用改写检测器默认开、或复用 `toolStrayRepeatGuard` 顺带打开。任何
  「先上线看看」的版本都会在模板化 agentic 流量上误伤，而误伤在面板上看不见（§3）。
